# 保險業務員 SaaS 平台（河馬保險對標版）

> 建立時間：2026-06-13
> 類型：新專案
> 狀態：待執行

---

## 你要做的事（一句話版）

建一個全新的獨立 Next.js 專案，讓保險業務員可以管理客戶、查詢商品、分析保障缺口，對標河馬保險的功能，沿用傳家知保的暖色系設計語言。

---

## 背景和動機

傳家知保是自己用的分析工具，這個新平台要做成可以**賣給其他業務員的 SaaS 服務**。
對標：河馬保險（hippoinsurance.com.tw）
差異化：更強的 AI 分析能力 + Google Drive 商品/保單整合 + 保障缺口可視化

---

## 核心功能清單

### 1. 客戶管理（CRM）
- 建立客戶檔案：姓名、生日、性別、職業、聯絡方式
- 每位客戶可掛多張保單
- 保單繳費資訊：繳費方式、繳費日期
- 自動提醒：保單到期、繳費截止日（email / 顯示於後台）
- 全險圖：彙整該客戶所有保單 → 顯示總保障 + 建議缺口

### 2. 商品查詢
- 搜尋商品資料庫（by 公司、名稱、計劃代號、險種）
- 資料來源 1：TII 保發中心（已有爬蟲）
- 資料來源 2：Google Drive 商品資料表（Excel/Google Sheets 自動同步）
- 點選商品 → 側拉 PDF 條款瀏覽

### 3. 保額輸入改進（保單建檔表單）
**單位規則**：
- 壽險 / 意外險：單位「萬」→ 輸入 `100`，系統顯示 `100 萬`
- 定額醫療（住院日額等）：單位「元/日」→ 輸入 `1500`，顯示 `1,500 元/日`
- 有給付表格的商品（如附約有 A/B/C 計劃）→ **下拉選計劃代號**，系統自動帶入該計劃的保額

### 4. AI 保單分析
- 上傳 PDF（或從 Drive 讀取）→ AI 解析保障結構
- 移植 specialistPrompts + aggregateInsurance 邏輯（從傳家知保）
- 輸出全險圖（InsuranceChart/InsuranceFormChart）

### 5. 多租戶架構
- 每位業務員（tenant）只能看到自己的客戶和資料
- 登入：Google OAuth（沿用）
- 訂閱方案（未來擴充）：目前先做單一方案

## 具體步驟

### Step 1：建立新專案骨架
- 在 `policy-analyzer/` 旁邊新建 `agent-platform/`（或另取名）
- Next.js 14 App Router + TypeScript + Tailwind
- 複製現有的 `globals.css` 暖色系主題變數
- 安裝：libsql（Turso）、next-auth、@google-cloud/drive

### Step 2：資料庫初始化
- 按新的 schema 建立 tables
- 移植 `lib/db.ts` 的 ensureInit 模式

### Step 3：Google OAuth 登入
- 移植 `app/api/auth/` 的登入邏輯
- 業務員第一次登入自動建立帳號

### Step 4：客戶管理頁（CRM）
- `/clients`：客戶列表，搜尋、標籤篩選
- `/clients/[id]`：客戶詳情 + 旗下保單列表 + 全險圖

### Step 5：保單建檔表單（含保額單位）
- 新增 / 編輯保單的表單
- 依險種自動切換保額輸入模式：
  - 壽險/意外：數字輸入 + 「萬」後綴
  - 醫療日額：數字輸入 + 「元/日」後綴
  - 有計劃表的商品：下拉選計劃 → 帶入保額

### Step 6：商品查詢 + Drive 同步
- 移植現有 `/api/products` 邏輯
- 新增 `/api/drive/sync` API：讀取 Google Drive 指定資料夾
  - 掃描 Sheets → 匯入商品資料表
  - 掃描 PDF → 建立保單檔案索引
- 商品列表頁 + 側拉 PDF 瀏覽（移植 `PdfViewerWithPages`）

### Step 7：AI 分析整合
- 移植 `lib/specialistPrompts.ts`、`lib/aggregateInsurance.ts`
- 移植 `/api/analyze` route
- 分析完自動存入 `policies.analysis_json`

### Step 8：全險圖（保障缺口分析）
- 移植 `InsuranceChart`、`InsuranceFormChart`
- 客戶頁面加入「一鍵生成全險圖」按鈕
- 對比建議保額 vs 現有保障，標示缺口欄位

### Step 9：提醒系統
- `/api/cron/remind`：掃描近 30/60 天到期的保單
- 後台顯示提醒列表
- Email 通知（移植 `lib/mailer.ts`）

## 可能遇到的風險

- **Google Drive 同步**：需要 OAuth 授權，Drive 資料夾結構要先定義好，才能寫 API
  → 做法：先約定資料夾格式（e.g. `商品資料/南山人壽/...`），再寫 sync

- **保額單位多樣性**：不同险种单位不一样，邊界情況多
  → 做法：先定義 `UNIT_MAP`（險種 → 單位），再處理特殊情況

- **移植元件相容性**：InsuranceChart 等元件有內建的 CSS 和依賴
  → 做法：整包目錄複製，不單獨拆元件

- **多租戶資料隔離**：每個 API route 都要驗 `advisor_id`
  → 做法：封裝 `getSessionAdvisor()` helper，API 一律先呼叫它
