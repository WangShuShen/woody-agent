# 保單審核頁 PDF 跳頁功能

> 建立時間：2026-06-08
> 類型：改善現有功能
> 狀態：待執行

---

## 你要做的事（一句話版）

在保單審核頁（`/review`）點擊右側任一給付項目時，左側的 PDF 自動跳到該項目所在頁面。

## 背景和動機

現在審核時要對照 PDF 確認 AI 的分析是否正確，但左邊 PDF 和右邊項目沒有連動，每次都要手動在 PDF 裡翻找對應頁。這個功能讓審核效率大幅提升。

---

## 具體步驟

### Step 1：修改 `db-extract` skill，讓 AI 輸出頁碼

- **做什麼**：在 `~/.claude/skills/db-extract/SKILL.md` 的 items JSON schema 裡，每個 item 加入 `"pageRef": 頁碼數字` 欄位
- **AI prompt 要求**：每個給付項目，記錄條款文字出現在 PDF 的哪一頁（整數，從第1頁算起）
- **產出**：`analyzed/*.json` 的每筆 item 都帶 `pageRef: number`
- **注意**：舊的 analyzed JSON 沒有 pageRef，這是正常的，Step 5 會處理

### Step 2：建立本地 PDF 代理 API 端點

- **做什麼**：新增 `GET /api/pdf-proxy/local?filename={filename}` 端點，從 `DB_DIR` 或本地暫存目錄讀取 PDF 並回傳
- **為什麼**：react-pdf 需要直接存取 PDF 二進位，無法透過 Google Drive iframe；本地暫存在 `100_Todo/projects/tmp/pdfs/` 的 PDF 可以直接讀取
- **降級方案**：若找不到本地 PDF，改用 Google Drive 下載 URL（`https://drive.google.com/uc?export=download&id={driveId}`）
- **產出**：能回傳正確 Content-Type: application/pdf 的端點
- **注意**：要確認 `DB_DIR` 環境變數指向正確目錄

### Step 3：安裝 react-pdf 並建立 `PdfViewerWithPages` 元件

- **做什麼**：`npm install react-pdf`；新增 `components/PdfViewerWithPages.tsx`
- **元件 props**：`pdfUrl: string`、`currentPage: number`、`onPageChange?: (n: number) => void`
- **元件功能**：顯示指定頁的 PDF，上方有「上一頁/下一頁/第N頁/共M頁」控制列
- **產出**：可獨立運作的 PDF 閱讀元件，支援程式化跳頁
- **注意**：react-pdf 需要設定 worker，參考官方文件用 `pdfjs-dist/build/pdf.worker.js`

### Step 4：替換 `ReviewDetail` 的 PDF 面板

- **做什麼**：修改 `components/ReviewView.tsx`，把 `PdfPanel` 元件改成 `PdfViewerWithPages`
- **URL 組成**：`/api/pdf-proxy/local?filename=${product.filename}` 或 Google Drive fallback
- **產出**：審核頁左側的 PDF 由 react-pdf 渲染，不再是 Google Drive iframe
- **注意**：沿用 `ReviewDetail` 現有的 `product.pdfDriveId` 和 `product.filename` 欄位

### Step 5：右側給付項目加點擊事件 → 左側 PDF 跳頁

- **做什麼**：在 `ReviewDetail` 加入 `activePage` 狀態（`useState(1)`）；`ItemsEditor` 的每一個 item row 加 `onClick`，呼叫時傳回 `item.pageRef`；`PdfViewerWithPages` 接收 `currentPage={activePage}`
- **UX 細節**：
  - 有 `pageRef` 的 item：點擊時左側 PDF 跳到對應頁，row 顯示頁碼徽章（如 `P.12`）
  - 沒有 `pageRef` 的 item（舊資料）：點擊無反應，row 顯示 `—`
- **產出**：點擊項目 → PDF 自動跳頁，體驗流暢

### Step 6：讓舊保單可以手動補頁碼（選擇性）

- **做什麼**：`ItemsEditor` 每個 item 右側加一個小的 `pageRef` 輸入框（`P. ___`），可手動填入頁碼；填入後存回本地 state（若要持久化，需呼叫 API 更新 analyzed JSON）
- **產出**：舊的沒有頁碼的保單，審核時可以手動補標
- **注意**：這個 step 若來不及或覺得不急，可以跳過，舊保單直接重跑 analyzer 取得頁碼也可以

---

## 預計成果

做完以後你會得到：
- 點擊右側任一給付項目 → 左側 PDF 自動跳到那一頁
- PDF 有上一頁 / 下一頁控制列，不再依賴 Google Drive iframe
- 每個 item 旁邊顯示頁碼（如 `P.12`），一眼知道條款在哪
- 以後新分析的保單都自動帶頁碼，不用手動標

---

## 不包含在這次的範圍

- 重新分析所有舊保單（Step 1 只影響新分析，舊的要手動或批次重跑）
- PDF 文字搜尋 / 關鍵字高亮
- 多 PDF 同時對照（目前只有單一 PDF）

---

## 可能遇到的風險

- **Google Drive PDF 存取問題**：若本地暫存不存在，需要從 Google Drive 下載；私人檔案需要登入 Google。降級方案：顯示「前往保發中心」連結
- **react-pdf 相容性**：某些舊版或掃描版 PDF 可能無法正確渲染頁數；降級方案：顯示 Google Drive iframe（原有功能）
- **PDF Worker 設定**：react-pdf 需要在 Next.js 環境正確設定 PDF.js worker，否則無法運作；照官方文件設定 `GlobalWorkerOptions.workerSrc` 即可解決
