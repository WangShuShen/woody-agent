# 保單審核頁面（/review）

> 建立時間：2026-06-04
> 類型：新功能
> 狀態：待執行

---

## 你要做的事（一句話版）

在傳家知保網站新增一個「保單審核」頁面，讓你每天打開就能看到待審核的保單清單，左邊看 PDF、右邊直接修改 AI 分析結果，確認後一鍵標記為「已審核」。

## 背景和動機

目前 AI 分析完的保單只能透過 Google Sheets 編輯，流程繁瑣。想在網站上直接完成「看 PDF → 修資料 → 審核通過」這個每日工作流，不再需要切換工具。

---

## 具體步驟

### Step 1：新增「待審核清單」頁面 `/review`
- **做什麼**：建立 `app/review/page.tsx`，從資料庫撈出 `verified = 0` 的保單列表
- **產出**：一個清單頁，顯示每張待審核保單的公司名、保單名稱、險種、上傳日期
- **注意**：`verified` 欄位已存在於 `products` 資料表，不需改 schema

### Step 2：新增左右分割的「審核檢視」頁面 `/review/[id]`
- **做什麼**：建立 `app/review/[id]/page.tsx`，左半邊嵌入 PDF（複用現有 `/api/pdf-proxy`），右半邊顯示分析結果
- **產出**：左右各佔 50% 的審核介面，左邊 PDF 可捲動，右邊顯示全險圖
- **注意**：PDF 從 TII 動態取得，若 TII 需要登入則顯示「前往保發中心」按鈕（複用現有邏輯）

### Step 3：讓右邊的全險圖可以直接編輯
- **做什麼**：點擊任一欄位（金額、限制條件、特別規定）後變成 input 框，按 Enter 或點其他地方儲存，底層呼叫現有的 `POST /api/correction`
- **產出**：每個欄位都可以點擊編輯，修改後底部出現「已儲存 ✓」提示
- **注意**：複用現有 `corrections` 資料表，不需新增 API 欄位

### Step 4：支援新增 / 刪除給付行
- **做什麼**：每個險種表格底部加「＋ 新增給付項目」按鈕；每行右側加刪除按鈕，刪除時以特殊值（如 `__deleted__`）寫入 correction
- **產出**：可以補上 AI 漏掉的給付項目，或刪除 AI 多讀的項目
- **注意**：刪除邏輯在前端過濾掉 `__deleted__` 記錄即可，DB 保留原始記錄供稽核

### Step 5：新增「通過審核」API 和按鈕
- **做什麼**：新建 `PATCH /api/products/[id]/verify` 路由，把 `products.verified` 從 0 改成 1；右側頂部加「✅ 通過審核」按鈕
- **產出**：點按鈕後，該保單從清單頁消失，代表已審核完畢
- **注意**：審核通過後跳回 `/review` 清單，方便繼續審下一張

### Step 6：在側邊導覽列加入「保單審核」入口
- **做什麼**：修改 `app/layout.tsx`，在現有導覽列的「保單分析」下方加入「保單審核」連結，並顯示待審核數量徽章（如：`3`）
- **產出**：側邊欄顯示「保單審核 3」，有未審核時一眼看得到
- **注意**：徽章數字從 `GET /api/review/count` 取得（需新建）

---

## 預計成果

做完以後你會得到：
- 每天打開 `/review` 就能看到有幾張保單等你審核
- 點進去後左邊 PDF、右邊可編輯分析結果，不用切換工具
- 直接在網站上改金額、刪錯誤項目、補漏掉的給付
- 按一下「通過審核」就完成，保單標記為已審核

---

## 不包含在這次的範圍

- **PDF 跳頁功能**（點給付項目自動跳到 PDF 對應頁）：需要在 AI 分析時記錄每項給付在 PDF 的頁碼，目前 JSON 沒有這個欄位，留作 Phase 2
- **自動觸發 Python 歸檔腳本**：審核通過後 `verified=1`，Python `db-archive` 可設定定時批次偵測並歸檔，不在這次網站範圍內
- **多人審核 / 角色權限**：目前只有單一管理員帳號

---

## 可能遇到的風險

- **TII PDF 需要登入**：部分保單的 PDF 可能因 TII 網站權限而無法直接取得，屆時顯示「前往保發中心」連結作為降級方案（現有邏輯已有）
- **分析 JSON 格式不一致**：不同險種的 `analysis_json` 結構略有差異（意外险 vs 醫療险），編輯元件需要能處理各種欄位格式
