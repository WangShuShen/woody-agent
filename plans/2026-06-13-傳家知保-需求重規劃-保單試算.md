# 傳家知保：需求重規劃 — 商品查詢 + 保額試算

> 建立時間：2026-06-13
> 類型：改善優化
> 狀態：待執行

---

## 一句話版本

在現有審核流程裡加入「給付公式填寫」步驟，AI 先給建議值、顧問確認調整，審核通過後使用者輸入保額就能立即看到每個給付項目的試算金額，完全不走 AI。

---

## 背景與動機

現有系統：上傳 PDF → AI 解析 → 顧問人工審核。審核完之後資料只能「看」，無法快速試算不同保額下的理賠金額。

目標：補上這塊缺口。

1. 審核時同步記錄「給付公式」（由顧問確認，AI 提供建議初稿）
2. 試算功能只查已審核通過的商品，公式人工確認，結果百分百正確
3. 移除無意義的歷史紀錄分頁

---

## 給付類型定義（五種）

| 類型 | type 值 | 說明 | 例子 |
|------|---------|------|------|
| 定額 | `fixed` | 每日/每次固定給付 | 住院日額 1,500 元/日 |
| 倍率 | `multiplier` | 保額 × 倍數 | 加護病房 = 保額 × 2 |
| 限額（實支）| `reimbursement` | 實際費用報銷，有上限 | 手術費實支，上限保額 × 30 |
| 範圍型 | `range` | 有最低～最高區間，依類別核給 | 手術費 5倍～40倍 |
| 一次性給付 | `lump_sum` | 特定事件觸發，只給一次 | 確診癌症給付保額 × 100 |

### 範圍型的費率單位（兩種，統一計算邏輯）

- `multiplier`：保額 × 倍數（定額醫療常見，保額單位 元/日）
- `percentage`：保額 × 百分比（壽險/意外險常見，保額單位 萬）

兩種本質相同，儲存 `rate_type` + `min_rate` + `max_rate`，試算時統一換算。

## 試算計算邏輯

輸入：`insured_amount`（保額數值）+ `base_unit`（元/日 或 萬）

| type | 計算方式 | 顯示 |
|------|----------|------|
| `fixed` | `insured_amount × multiplier` | `X 元/日` |
| `multiplier` | `insured_amount × multiplier` | `X 元` |
| `range` (multiplier) | `insured_amount × min_rate` ～ `insured_amount × max_rate` | `X 元 ～ Y 元` |
| `range` (percentage) | `insured_amount × min_rate/100` ～ `insured_amount × max_rate/100` | `X 元 ～ Y 元` |
| `reimbursement` | 上限 = `insured_amount × multiplier` | `實支，上限 X 元` |
| `lump_sum` | `insured_amount × multiplier` | `X 元（一次性）` |

- 可新增項目（AI 沒抓到的）、可刪除項目（AI 抓錯的）
- 備註欄選填，給「依手術類別」「年度累計」等說明用

## 資料庫異動

### products table 新增兩欄

```sql
ALTER TABLE products ADD COLUMN formula_json TEXT;
-- 存給付公式，格式見上方規格

ALTER TABLE products ADD COLUMN formula_verified INTEGER DEFAULT 0;
-- 0 = 公式未填，1 = 顧問確認完成
```

**開放試算條件：`verified = 1` AND `formula_verified = 1`**

## API 端點規劃

| 方法 | 路徑 | 功能 | 認證 |
|------|------|------|------|
| GET | `/api/products?verified=1&formula=1` | 只回傳可試算的商品 | JWT |
| PUT | `/api/products/[id]/formula` | 儲存/更新給付公式 | JWT（顧問）|
| POST | `/api/products/[id]/trial` | 輸入保額，回傳試算結果 | JWT |

## 實作步驟

### Step 1：資料庫 Schema 異動
- 做什麼：對 Turso DB 執行兩個 ALTER TABLE ADD COLUMN
- 注意：LibSQL 支援 ADD COLUMN，不影響現有資料

### Step 2：後端 — 公式儲存 API（PUT /api/products/[id]/formula）
- 驗證 JWT（只有登入的顧問可操作）
- 接收 formula_json，驗證格式後寫入 DB
- 同時設定 formula_verified = 1

### Step 3：後端 — 試算計算 API（POST /api/products/[id]/trial）
- 讀取 formula_json
- 根據 type 套用對應計算邏輯
- 格式化金額後回傳（純數學，不走 AI）

### Step 4：前端 — 審核頁加入給付公式區塊
- 從 analysis_json 自動帶入建議值（反推 multiplier = 分析金額 ÷ 保額）
- 支援五種類型切換
- 範圍型展開最低/最高兩欄
- 填完才能按「審核通過」

### Step 5：前端 — 商品查詢加入試算入口
- 商品列表只顯示 verified + formula_verified = 1 的商品
- 商品抽屜加「試算」按鈕
- 展開後輸入保額，顯示結果表格

### Step 6：移除歷史紀錄分頁
- 從導覽列移除「歷史紀錄」項目
- 刪除 `/history` 路由頁面

## 預計成果

1. 顧問審核一份保單後，同步確認給付公式，一次完成
2. 輸入保額立即看到所有給付項目試算結果，範圍型顯示最低～最高區間
3. % 和倍數統一換算，不管哪家公司怎麼表達都能處理
4. 導覽列移除歷史頁，介面更簡潔

## 可能的風險

- **analysis_json 格式不一致**：不同版本 AI 輸出欄位名稱略有差異，自動帶入建議值時需寬鬆匹配，讓顧問手動確認。
- **formula_json 格式驗證**：前端送出前要驗證每個 item 都有必要欄位（label、type、數值），避免存入不完整的公式。
- **Turso ALTER TABLE 限制**：LibSQL 只支援 ADD COLUMN，這次只新增欄位，沒有問題。
